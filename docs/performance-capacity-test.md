# 클러스터 동시 접속 성능 측정

## 목적

GameServer 한 프로세스와 3개 GameServer 클러스터가 오류 없이 유지할 수 있는 동시 접속자 수를 동일한 조건으로 반복 측정한다.

## 실행 준비

Release x64로 솔루션을 빌드하고 클러스터를 실행한다.

```powershell
.\scripts\Stop-ServerCluster.ps1
.\scripts\Start-ServerCluster.ps1 -Configuration Release
```

## 단일 GameServer 기준 측정

```powershell
.\x64\Release\TCPStressClient.exe 127.0.0.1 7001 400 20 5 30
```

인수 순서는 IP, 포트, 클라이언트 수, 송신자 수, 송신자별 초당 메시지 수, 테스트 시간이다.

## 3개 GameServer 동시 측정

```powershell
.\scripts\Run-ClusterStressTest.ps1 `
    -Configuration Release `
    -ClientsPerServer 400 `
    -SendersPerServer 20 `
    -MessagesPerSecond 5 `
    -DurationSeconds 30
```

위 조건은 GameServer마다 400명, 클러스터 전체 1,200명을 의미한다. 각 실행 결과는 `test-results` 아래의 시간별 폴더에 저장되며 Git에는 포함되지 않는다.

## 단계별 한계 탐색

먼저 메시지 빈도를 고정하고 GameServer별 접속자 수를 올린다.

```text
400 → 500 → 600 → 700 → 800 → 900 → 1,000
```

실패 구간이 확인되면 50명 단위로 범위를 좁힌다. 예를 들어 500명이 성공하고 600명이 실패하면 550명을 측정한다.

## 현재 부하 생성기의 한계

현재 TCPStressClient는 가상 클라이언트마다 운영체제 스레드를 하나씩 생성한다. 동일 PC에서 수천 개의 연결을 시도하면 서버보다 부하 생성기의 스레드와 로컬 시스템 자원이 먼저 포화될 수 있다.

실제 측정에서도 클러스터 전체 2,100명을 설정했지만 연결 성공 수가 설정값보다 크게 부족했다. 따라서 이 결과는 서버가 2,100명을 처리한 결과가 아니며 최종 성능 수치로 사용하지 않는다.

```text
1,200명 설정 → 실제 연결 수가 설정값보다 적음
2,100명 설정 → 실제 연결 수가 1,200명 테스트보다도 적음
```

이 단계의 테스트는 다중 GameServer에 동시에 부하를 전달하고 결과를 수집하는 자동화 검증으로 사용한다. 서버의 실제 대규모 동시 접속 한계는 IOCP 기반 부하 생성기 또는 별도 부하 장비를 사용한 후 다시 측정한다.

## 성공 기준

- 연결 및 로그인 실패가 없다.
- 송수신 오류가 없다.
- 실제 수신량과 예상 수신량이 같다.
- SendQueue 최대 용량 초과가 없다.
- P95와 P99 지연시간이 프로젝트의 목표 범위 안에 있다.
- 테스트 중 프로세스가 종료되지 않고 메모리가 지속해서 증가하지 않는다.

프로파일러는 최대 동접을 직접 계산하지 않는다. 부하 테스트가 성공과 실패의 경계를 찾고, Visual Studio CPU Usage는 그 경계에서 병목 함수와 시스템 호출을 분석하는 데 사용한다.

## 결과 표기

```text
빌드: Release x64
환경: 단일 PC 로컬 테스트, 채팅 로그 활성화
GameServer: 3개
프로세스별 동시 접속: 400명
클러스터 전체 동시 접속: 1,200명
테스트 시간: 30초
오류: 0
```

동일 PC에서 서버와 부하 생성기를 함께 실행하므로 이 결과는 로컬 검증값이다. 실제 서비스 용량으로 표현하려면 별도 부하 생성 장비에서 같은 조건을 재검증해야 한다.
